[TabBottomSheet] Skip fade-in delay when WebView size is unchanged

When exiting resizing mode with unchanged WebView dimensions,
armPostResizeFadeIn() already skips waiting for runOnNextFrame(), but
onNextFrameAfterResize() still unconditionally applied
FADE_ANIMATION_DELAY_MS (250ms) to the fade-in animator.

Pass a delayFadeIn flag to onNextFrameAfterResize() so the 250ms start
delay is only applied when sizeChanged is true (where CSS/JS reflow
settling is needed), allowing no-op resizes to fade the WebView back in
immediately.

UnexpectedDeducer held references to the handler and its arguments in
a tuple and only invoked the handler when it was converted to the
function's return type. That let a handler return a prvalue of an

immovable type from a handler was changed in crrev.com/c/8856336.

returned by reference, and to the error of the failed result when

base::expected<T, std::string_view>.

A reload that receives a server redirect still commits with a reload
load type in the renderer, and when the redirect target shares a

moving them after the URL-equality early return. This isolates
cross-origin redirects while preserving key, id, and state across
same-origin redirects and leaving same-document kFragment navigations
unchanged.

[ash] Migrate direct disk space callers to AmountOfDiskSpace()

SysInfo::AmountOfFreeDiskSpace() and AmountOfTotalDiskSpace() return an
int64_t and are slated for removal in favor of
SysInfo::AmountOfDiskSpace(), which returns the total and available

chrome/browser/ash:

- NearbyShareSessionImpl's CalculateRequiredSpace(): a failed query

  the total and available space from a single query.
- HasEnoughDiskSpace() in the Phone Hub camera roll download manager:
  compare using ByteSizeDelta so that a negative file size reported by
  the phone does not crash.
- AddDiskSpaceInfoToEvent() in ArcAppInstallEventLogger, which now gets
  the total and available space from a single query.
- ChromeCameraAppUIDelegate::StorageMonitor, whose thresholds are now
  ByteSize constants. The `current_storage < 0` check relied on nullopt
  comparing below zero; check for a failed query explicitly instead.
- The two unit tests that called AmountOfFreeDiskSpace() or
  AmountOfTotalDiskSpace() directly.

Callers that bind AmountOfFreeDiskSpace() as a callback, and
AmountOfTotalDiskSpace() callers in other files, are left for follow-up
CLs.

[chrome popup window] Fix setAllowOverlapCaptionBar with background

When PopupWindow has a background drawable set (including every
AnchoredPopupWindow), Android wraps contentView in PopupBackgroundView
inside PopupDecorView. ChromePopupWindow#showAtLocation previously read
contentView.getParent().getLayoutParams(), which returned
FrameLayout.LayoutParams instead of WindowManager.LayoutParams, causing
setAllowOverlapCaptionBar(true) to silently no-op.

Walk to contentView.getRootView() (PopupDecorView), guard
updateViewLayout on isShowing() and an attached parent, and clear only
WindowInsets.Type.captionBar() instead of all fit-inset types so status
bar, navigation bar / taskbar, and system overlay clamping remain
intact.

TabStripContextMenuCoordinator.buildMenuWindow() is currently the sole
caller of setAllowOverlapCaptionBar(true) in Chromium. Its placement is
unchanged because it also sets setVerticalOverlapAnchor(true) (which
clamps y to windowRect.top in AnchoredPopupWindowUtils before
showAtLocation runs), while keeping non-caption-bar fit-inset types
preserves taskbar clamping at the bottom of the vertical tab strip. This
fix unblocks vertical-tabs bookmark popup alignment in
crrev.com/c/8778832, which keeps verticalOverlapAnchor false so its top
shadow can overlap the caption bar.

[Actor] Let the user stop a running ExecuteJs script

ExecuteJsTool::Cancel() did nothing, and the renderer handles
ChromeRenderFrame.CancelTool() on its main thread, which a running
script blocks. So when the user stopped or took over a task, the page
stayed unresponsive until the script timed out, which can take up to a
minute.

- Add actor.mojom.ExecuteJsCanceller. The browser always sends its
  receiver in the ExecuteJsAction, and the renderer binds it on its IO
  thread, so that it can terminate the script while the script blocks
  the main thread. Since ToolAction can't be cloned anymore,
  ExecuteJsToolHost builds the action when it invokes the tool, and
  ScriptToolHost clones only its ScriptToolAction.
- Add ScriptCanceller, which terminates the tool's script from any
  thread. Like the timeout, it only terminates script while a
  ScopedTimeoutWatchdog watches it, so it can't terminate unrelated
  script. It also covers converting the result and formatting the
  arguments of console.* calls, including in callbacks that the script
  scheduled, which can run page JavaScript.
- Implement ExecuteJsTool::Cancel(), which terminates the script if it
  spun a nested run loop, and stops waiting for a returned promise.
- ExecuteJsToolHost cancels the tool in the renderer, through both
  ExecuteJsCanceller and CancelTool(), whenever it stops waiting for
  the tool before the tool finishes: e.g. when the user stops or takes
  over the task, when the tool times out, when its frame navigates or
  goes away, and when its tab moves to another window or closes, so
  that the script doesn't keep blocking the page, or other pages that
  share its renderer.
- ToolExecutor doesn't start a tool while a ScopedTimeoutWatchdog is
  active, i.e. while watched script is still on the stack, e.g. an
  ExecuteJs script that spun a nested run loop in which its tool was
  cancelled, since the script's pending termination would hit the new
  tool's script instead.
- A cancelled tool reports kInvokeCanceled rather than a timeout.

Reland "ozone/wayland: Report window occlusion when suspended or sleep-stalled"

This is a reland of commit 520461d4a5c09690d75e76ac94d936a0c30836f0.

The original was reverted because it failed to compile: it added a
private WaylandWindow::shutting_down() getter while d5e7e46ca4800
("[ozone/wayland] Track active subsurface bubble on
WaylandToplevelWindow") landed a public one, so the two declarations
collided ("class member cannot be redeclared"). The reland drops the
duplicate getter and uses the existing public one. No other changes.

Original change's description:
> ozone/wayland: Report window occlusion when suspended or sleep-stalled
>
> When a Wayland compositor enters an inactive display-sleep state (such
> as Weston's idle DPMS-off mode or Sway's output power-off), it stops
> signaling wl_surface.frame callbacks without sending any xdg_toplevel
> state events. WaylandFrameManager holds pending frames waiting for the
> previous wl_callback, halting BeginFrames to the renderer. Because
> WaylandToplevelWindow never reported PlatformWindowOcclusionState,
> WebContents remained Visibility::VISIBLE and document.visibilityState
> stayed "visible", allowing auto-refreshing pages (such as Grafana) to
> queue fetch payloads and requestAnimationFrame callbacks indefinitely
> until renderer OOM.
>
> Report PlatformWindowOcclusionState changes from WaylandToplevelWindow
> via PlatformWindowDelegate::OnOcclusionStateChanged(), gated behind an
> enabled-by-default WaylandWindowOcclusion killswitch:
> - kHidden when the window is hidden;
> - kOccluded when xdg_toplevel::suspended is active or when an in-flight
>   wl_surface.frame callback goes unanswered for 3 seconds;
> - kVisible otherwise, recovering immediately when wl_callback.done
>   arrives on display wake or when xdg_toplevel::suspended clears.
>
> The frame callback timeout applies on every compositor, not only to
> display sleep. wl_surface.frame says "A server should avoid signaling
> the frame callbacks if the surface is not visible in any way, e.g. the
> surface is off-screen, or completely obscured by other opaque
> surfaces", so windows on another workspace or fully covered by other
> windows are reported as occluded too, matching what Mutter and KWin
> report via xdg_toplevel::suspended. The 3 second delay matches Mutter's
> delay before sending suspended.
>
> A client-side minimize is not reported as hidden: the compositor never
> confirms minimization, so the window could be restored without being
> activated and would then stop painting. Compositors that suspend
> minimized windows report them as occluded instead.
>
> Reporting kOccluded transitions WebContents to Visibility::OCCLUDED
> (PageVisibilityState::kHidden) and throttles background timers while
> preserving PlatformWindowState (including fullscreen and window
> geometry), VideoCaptureLock, and Picture-in-Picture semantics.

[test] Match WM_NCMOUSEMOVE in Win InputDispatcher

In ui_controls::SendMouseMoveNotifyWhenDone on Windows,
InputDispatcher's WH_MOUSE hook previously only matched WM_MOUSEMOVE.
Moving the cursor over non-client hit-test regions such as tab strips
and caption bars emits WM_NCMOUSEMOVE instead, causing InputDispatcher
to stall until TestTimeouts::action_timeout() (30s) before invoking the
completion callback anyway. Match WM_NCMOUSEMOVE alongside WM_MOUSEMOVE
since both carry screen coordinates in MOUSEHOOKSTRUCT::pt.

On win-rel interactive_ui_tests, this eliminates the 30s hook timeouts
across all 5 affected non-client/caption tests (187.52s -> 8.98s total,
-178.54s / -95.2%):

  2.13s, 32.05s -> 2.11s, and 31.09s -> 1.14s.

  31.21s -> 2.27s.

[MultiWindow] Soft-close unrecovered crashed windows into Recent Tabs

Browser crashes bypass normal window closure bookkeeping, and dismissing
crash recovery previously cleared recoverability without recording
closure timestamps. As a result, reopening closed entries after a crash
ranked older closed windows or tabs ahead of the crashed windows.

* Soft-close unrecovered regular windows on crash recovery dismissal
  (and taskless regular windows on incognito relaunch) with a shared
  closure timestamp and notify Recent Tabs.
* Clear persisted closure timestamps when windows initialize so active
  windows do not retain stale background closure times.
* Centralize recently closed window timestamp fallback, filtering, and
  ordering (by closure time descending, breaking ties by last-accessed
  time descending) in MultiInstanceManagerApi31 (via helpers introduced
  in MultiWindowUtils), and use the same tie-breaker when evicting
  excess inactive instances.

views: Close menus when the owner's window is moved or resized

Menus are positioned relative to their owner widget when shown. When
the window manager tiles the browser window (e.g. Super+Arrow on
Linux), the owner's show state does not change, so the existing
show-state handling from crbug.com/40914555 does not close the menu.
The App Menu and context menus then stay at their old position,
detached from the window.

Observe the owner's primary window widget and close all menus when its
bounds differ from those at the time the menu was shown. Using the
primary window resolves bubbles (e.g. toasts) to the browser window,
so bounds changes Chrome makes to the bubble itself are ignored, and
the comparison ignores move notifications that do not change the
bounds (seen on X11 after entering fullscreen).

On ChromeOS, shelf context menus now also close when the shelf hides
for a pinned window, since the hotseat widget moves offscreen.

This CL schedules deferred HistoryBackend initialization once the first
browser window finishes its first presentation, while keeping the
AfterStartupTaskUtils task as a fallback when no window presents.

for the initial New Tab Page to finish loading. On profiles with

HistoryBackend runner and blocked NTP load completion, leaving favicons
