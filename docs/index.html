[omnibox] Fix and re-enable Full WebUI Omnibox interactive tests

Re-enable multiple interactive UI tests for the Full WebUI Omnibox that
were previously disabled or marked as flaky on Windows, Mac, and Linux
bots.

To achieve stability across platforms, this change updates the global
browser setup function. Rather than completely disabling
`BringBrowserWindowToFront()`, the setup now explicitly activates the
`BrowserView` before bringing the window to the front. This resolves
timeouts and correctly handles cases where the WebUI popup widget
already holds foreground focus.

Additionally, this commit includes the following test improvements:
* Updates mouse click targets and coordinates for better reliability
  (e.g., clicking the right edge of the toolbar instead of the tab
  strip frame grab handle).
* Enhances AIM interactive tests to explicitly verify text selection
  ranges and cursor positions when the popup is dismissed and focus
  is restored to the Omnibox.
* Inserts a `WaitForPopupTransitionLockout()` step to properly
  synchronize the test that rapidly opens multiple New Tab Pages.

[Contextual Tasks] Persist side panel toolbar

When switching away from a tab with an open Contextual Tasks side panel
to a tab without a task and then switching back, SidePanelCoordinator
destroys and recreates ContextualTasksWebView. While the task's content
WebContents is cached by ContextualTasksSidePanelCoordinator and paints
immediately, ContextualTasksWebView previously created a fresh toolbar
and ghost loader WebContents on every view creation, causing the toolbar
to visibly pop in after the content.

This change caches the toolbar and ghost loader WebContents in
ContextualTasksPanelHostDesktop for the lifetime of the browser window
and reattaches them whenever ContextualTasksWebView is recreated. It
also sets the initial darkMode loadTimeData boolean in
ContextualTasksUIBase using ShouldUseDarkMode(profile) so the toolbar's
first paint matches the active theme.

mac: Sync first responder between toolbar and main window on click

This is a defensive fix for crbug.com/563226016.

We don't know how the issue happens (it can no longer be reproduced),
but there're reports about the toolbar NSWindow and browser NSWindow
sometimes having different first responder (they are supposed to share
first responder).

To defence from the issue happening again, this CL forces a
synchronization of first responder on mouse click in
RenderWidgetHostViewCocoa (the WebUI Toolbar).

Before this CL, clicking the WebUI Location Bar does not recover from
the bad state, because AppKit skips -makeFirstResponder: when the WebUI
Toolbar's RWHVCocoa is already the first responder of the toolbar
NSWindow.

Also, let WebUIToolbarEventForwarder routes events to
RenderWidgetHostViewCocoa (they were routed to RenderWidgetHost), since
the first responder sync code exists only in RWHVCocoa.

As a side effect, this largely fixes a separate issue that there is no
cursor update in the Omnibox cutoff (e.g., no I-Beam when hovering text,
crbug.com/557075194). This is because RWHVCocoa forces a cursor sync on
mouse move.

Anchor popovers to ::interest-button when it triggers interest

Before this CL, when an interest invoker showed a popover, the
popover's implicit anchor was always the originating element. That was
true even when interest was shown by activating the element's
`::interest-button` pseudo element.

With this CL, if the `::interest-button` is activated, and the target
popover is implicitly anchored to the originating element, the implicit
anchor becomes the `::interest-button` instead.  This makes sense,
since in this case the user has clicked the `::interest-button`, so it
feels more natural to have an anchored popover anchor to that button,
rather than the originating element.

[Bookmarks] Fix back press dismissal at root in folder picker

Previously, BookmarkFolderPickerCoordinator returned an always-true
back press supplier when the desktop bookmarks dialog flag was
disabled. Because BackPressHelper registers its callback after
BookmarkFolderPickerActivity registers its root OnBackPressedCallback,
the LIFO dispatch order kept BackPressHelper enabled even at the root
folder. Pressing back at the root folder was intercepted by
BackPressHelper and ignored when handleBackPress returned failure,
preventing the activity root callback from finishing the activity.

Always delegate getHandleBackPressChangedSupplier to the mediator so
that BackPressHelper disables its callback at the root folder and
allows the activity root callback to dismiss the picker.

[selection] Add interaction options to the selection overlay

Add a `glic.selection.InteractionOptions` mojom struct with per-session
flags that change how the user can interact with the selection overlay:
  - `hide_handles`: hide the handles and fix the region.
  - `disable_multi_select`: disable multi-region selection.

The options are passed through `ShowWithSelection()` and reset when the
overlay closes. They are sent to the WebUI through the new
`SelectionOverlayPage.SetInteractionOptions()` before each screenshot.

This CL only adds the flags and the pipeline. The overlay behavior for
each flag will follow in later CLs. All flags default to false, so the
existing region capture behavior is unchanged.

[aim-drive] Show Drive sign-in promo from WebUI Omnibox

When kWebUIOmniboxFullPopup is enabled and a signed-out user selects
"Add from Google Drive" from the Omnibox "+" context menu, the WebUI
Omnibox popup remained open and competed for widget activation with
ComposeboxDriveSignInPromoView. Specifically, deactivating the AIM popup
transitions from kAim to kFull via CloseUI(), and the async ClearPopup
callback in OmniboxAimPopupWebUIContent::ApplyInputAndCleanup
unconditionally called popup_view->OnFocus() when kWebUIOmniboxFullPopup
was enabled, stealing activation from the promo bubble and immediately
dismissing it.

1. Explicitly closes the Omnibox popup (StopAutocomplete(true) and
   SetPopupState(kNone)) in
   ContextualSearchboxHandler::OnDriveUploadClicked before showing the
   Drive sign-in promo, and recreates
   composebox_drive_signin_promo_controller_ for the current active
   tab's WebContents.

2. Only calls popup_view->OnFocus() in
   OmniboxAimPopupWebUIContent::ApplyInputAndCleanup during an explicit
   WebUI close (CloseUI()) or when the browser window widget is
   currently active, so clicking the page content still restores focus
   to the Full WebUI popup while external bubbles retain activation.

3. Changes OmniboxContextMenu::parent_widget_ from raw_ptr to
   base::WeakPtr<views::Widget> to avoid a DanglingRawPtrReleased crash
   when the popup widget closes during ExecuteCommand() before
   MenuRunnerImpl asynchronously deletes the menu.

[Ad Detection] Evaluate sticky ad containers from the frame owner

The sticky ad heuristic skips ads whose outermost container is static,
to filter out in-flow ads that only appear stationary due to layout
shifts (e.g., scroll anchoring). For ads in (local, non-ad) subframes
(which can occur when a root iframe misses ad tagging), this was
evaluated within the subframe's document. However, subframe content
often moves with the main frame's scroll exactly as its frame owner
does, so this caused false negatives for in-flow ads within a positioned
(e.g., fixed) <iframe>.

This CL updates the positioning check for subframe ads to inspect the
outermost frame owner element in the embedding frame instead.

audio: Fade VoiceIsolationHandler enable/disable transitions

Toggling voice isolation switched abruptly between the microphone
signal and the voice isolation output, producing audible clicks on
both edges.
Smooth both transitions within a single buffer using a precomputed
rising half-Hann (sin^2) window. No extra state machine is needed and
the real-time thread does not allocate.
On OFF -> ON, voice isolation is primed from silence, so it is fed a
faded-in copy of the microphone signal to keep its delayed output from
starting with a step. The delivered audio crossfades from the
microphone signal to the voice isolation output.
On ON -> OFF, voice isolation runs one last time and its output is
crossfaded back to the microphone signal. Its buffers are then cleared
so that stale speech does not leak when it is re-enabled. The voice
isolation output lags the microphone by its algorithmic delay, so this
transition still skips the buffered lookahead; the crossfade only
removes the amplitude discontinuity.
