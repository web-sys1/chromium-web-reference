Disable SYN retransmissions for loopback on Windows

When connecting to a closed port on Windows, the TCP stack will
retransmit the SYN packet multiple times before reporting an
ECONNREFUSED error. By default, this takes roughly 2 seconds.

For web developers running local servers (which often bind only to
127.0.0.1), this creates a significant performance penalty. Chromium's
TransportConnectJob tries IPv6 (::1) first and waits either for it to
finish or for a fallback timer (~300ms) before trying IPv4. Because the
::1 attempt stalls for 2 seconds rather than failing immediately, every
new connection to localhost incurs the full 300ms fallback penalty.

This CL avoids the SYN retransmission stall by explicitly disabling SYN
retransmissions for loopback connections on Windows 10 version 1709 and
above.
