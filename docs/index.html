[Cast] Use base::BindPostTask for TCP connect reply

CastSocketImpl::DoTcpConnect() hops to the UI thread to call
NetworkContext::CreateTCPConnectedSocket(), and the reply has to come
back on the socket's own sequence. That return hop was implemented by a
hand-rolled OnConnected() trampoline that unpacked all six callback
arguments and re-posted them to a hard-coded
content::GetIOThreadTaskRunner({}).

Replace it with base::BindPostTask(), binding the sequence that
DoTcpConnect() is running on. This is behavior-preserving today, since
CastSocketImpl runs on the IO thread, but it removes the hard-coded
thread reference and the argument-forwarding boilerplate.

This is a prerequisite cleanup for moving the Cast stack off the IO
thread: with the reply sequence derived from the caller rather than
hard-coded, CastSocketImpl no longer has to be told which thread it
lives on.

No functional change intended.
