Bypass autocomplete edits in Omnibox Undo history.

This CL prevents certain programmatic autocomplete text modifications
(insertions and deletions) from polluting the undo history of the
Omnibox.

Any changes applied to the Editable are subject to UndoInputFilter
creation, and many of these directly conflict with how Autocomplete is
designed to work.

The change proposes an InputFilter helper class that takes a snapshot
of current filters before and after undo-impacting operation is
performed, allowing us to restore the exact set of filters that were
captured just before our programmatic change took place.

This approach won over SpannableStringBuilder alternative, which
required us to manually identify which filters to keep and which to
reject via reflection. In theory the reflection approach could be
skipped, as Omnibox rarely filters content, but in practice this would
leave a landmine for any future work in this area.

This direction sets the stage for capturing undo filters as part of
Persisted Tab Editing State, allowing undo to function when user jumps
to another tab.
