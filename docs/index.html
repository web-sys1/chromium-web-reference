Include what you use around browser_view.h, part 3 of 3

These files reach types such as views::BubbleDialogDelegateView and
FullscreenController only because
chrome/browser/ui/views/frame/browser_view.h happens to pull them in
transitively. browser_view.h is about to stop doing so, when it is
split into its own GN target and drops the two includes that keep it
tied to the //chrome/browser/ui:ui monolith.

Adding the includes here is a no-op today and lets that split land
without breaking these files. Where the use sits behind a build guard
the include is placed inside the same guard. No behaviour change.
