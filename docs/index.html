[network] Allow kSameOrigin credentials with disable_web_security

crrev.com/c/8278433 moved the evaluation of CredentialsMode::kSameOrigin
from CorsURLLoader to url_loader_util::SetRequestCredentials() via
IsSameOriginOrAccessAllowed(). However, when URLLoaderFactoryParams has
disable_web_security enabled (e.g. via --disable-web-security or
Android WebView's allow_universal_access_from_file_urls for file://
origins), CorsURLLoaderFactory bypasses CorsURLLoader and
origin_access_list is not populated for arbitrary cross-origin targets.
As a result, cross-origin requests with default kSameOrigin credentials
mode had their credentials disallowed in SetRequestCredentials().

Pass URLLoaderFactoryParams::disable_web_security to
SetRequestCredentials() during initial request configuration and on
redirects, and allow kSameOrigin credentials and client certificates
when disable_web_security is true, guarded by a new kill-switch feature
kAllowSameOriginCredentialsWithDisableWebSecurity.

entry (GetLastRowForVisitByVisitTime and GetURLRow), which adds up when
all journeys are resolved at once. Add JourneysDatabase methods that
look up the history entries of one or all journeys with a single query
joining them with visits and urls, reporting per entry whether the
visit or URL is missing.

the largest ID for a timestamp is used (the end of a redirect chain),
and a URL row with an invalid URL counts as missing. Resolution
switches over in a follow-up CL.

[chromium-bidi] Implement autofill.trigger

Implement the `autofill.trigger` WebDriver BiDi command defined by the
Autofill Event specification [1], by mapping it to CDP
`Autofill.trigger`, which waits for provided inputs and then This is a
port of [2], updated to the specification as published.

Bidi:
- Generate the `autofill` module types from the WICG/autofill-event spec
  with `tools/update_bidi_types.py`. Teach the generator to import core
  namespaces referenced by extension specs, e.g.
  `browsingContext.BrowsingContext` and `script.SharedReference`.
- Add `AutofillProcessor`, which checks that the element is a form
  control with a form owner and that exactly one of `card` and `address`
  is provided, maps `autofill.FieldName` values (HTML autofill field
  names) to Chromium autofill field types, and maps CDP errors to BiDi
  errors.
- Add unit tests and E2E tests, including same-origin and cross-origin
  iframes.

CDP:
- Make `Autofill.trigger` respond only once the values have been applied
  to the form fields, so that clients can read them as soon as the
  command returns, without polling. After sending the values to the
  renderers, the handler triggers form extraction in all frames and
  responds when it finishes. Form extraction goes over the same
  `mojom::AutofillAgent` pipes as the fill, so by then the renderers
  have applied the values.
 - Document this in `Autofill.pdl`, and add
  `DevToolsAutofillTest.TriggerRespondsAfterFillIsApplied`.

[MenuSimplification] Prevent duplicate Reading Mode context menu entries

In RenderViewContextMenu, Reading Mode
(IDC_CONTENT_CONTEXT_OPEN_IN_READING_MODE) could be appended more than
once in two edge cases:
1. In the legacy/disabled menu simplification path with text selection
   in an editable field, AppendOtherEditableItems() appends reading mode
   first, followed by the ITEM_GROUP_SMART_SELECTION block in
   InitMenu().
2. In the MenuSimplification path when the
   ReadAnythingMenuShuffleExperiment arm kPlaceAtBottom is active,
   AppendPageItems() appends reading mode, and InitMenu() subsequently
   appends it again at the bottom of the menu.

This CL prevents duplicate items by:
1. Adding an idempotency guard at the entry of AppendReadAnythingItem()
   to check if IDC_CONTENT_CONTEXT_OPEN_IN_READING_MODE is already
   present.
2. Skipping the kPlaceAtBottom hook in InitMenu() when
   took_simplified_page_items_path is true, since simplified page items
   already append reading mode.

Unit tests are added covering both scenarios.
