Notify Fusebox when activation chip selection changes

When keyboard tabbing onto the AI Mode activation chip, the Omnibox text
was not clearing because LocationBarMediator wrapped the activation chip
with a generic SelectableView that only updated the View's selected
state without notifying FuseboxCoordinator.

The CL overloads LocationBarMediator#wrapSelectableView to accept an
optional onSelectionChanged callback and forwards selection updates to
FuseboxCoordinator. It also caches the activation chip View and exposes
getActivationChip() to avoid redundant findViewById lookups.
