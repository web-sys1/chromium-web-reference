JNI Zero: Narrow JniTypeToken visibility

JNI Zero generates each class's `<Class>Jni` proxy in the same Java
package as the enclosing class. A nested `JniTypeToken` interface (and
`@NativeMethods` `Natives` interface) therefore only needs
package-private visibility unless it is referenced across package
boundaries.

Drop the redundant `public` modifier from `JniTypeToken` declarations in
`third_party/jni_zero/README.md` and in classes whose tokens are only
referenced within their own package (`TabUnderlineManager`,
`MostVisitedSitesBridge`, `ExtensionControlHandler`, `LocationBarModel`,
`ContentSettingsObserver`, and `CookieControlsBridge`), as well as
`ExtensionControlHandler.Natives`.

[test] Gate kSpareRendererForSitePerProcess on EXPENSIVE_TEST_LOGIC

When features::kSpareRendererForSitePerProcess is enabled (the default
on desktop), SpareRenderProcessHostManager::PrepareForFutureRequests
automatically spawns a background spare renderer process after every
navigation. In browser_tests, the vast majority of tests exit right
after their initial navigation without ever consuming the newly spawned
spare renderer, wasting ~2.5-3.0% of total browser_tests CPU time
(~150-180 ms CPU per test) on process launch, zygote fork, and V8/Blink
initialization.

Disable features::kSpareRendererForSitePerProcess by default in
InProcessBrowserTest::Initialize() when !EXPENSIVE_TEST_LOGIC_IS_ON()
(such as on CQ release trybuilders), while keeping it enabled on CI and
local developer builds to preserve broader test coverage. Update tests
that rely on automatic background spare renderer creation to warm up a
spare explicitly or enable the feature via ScopedFeatureList.

[DevTools] Restrict DevToolsUI TrustPolicy and sticky opener taint

Previously, DevToolsUI inherited the default WebUIController
TrustPolicy::kTrusted for all devtools:// documents, including remote
frontends and unprivileged popups. When a renderer-initiated navigation
occurred on a frame with a kTrusted WebUI, Navigator::RequestOpenURL and
NavigateFromFrameProxy cleared is_renderer_initiated. Combined with
closing the remote opener before re-navigating a
devtools://devtools/blank popup, a popup opened by a remote frontend
could bypass the opener-chain and renderer-initiated checks in

[a11y] Avoid temporary shape results in inline text box serialization

This change reduces Blink accessibility CPU time by 4.99% and overall
renderer main thread (`CrRendererMain`) CPU time by 0.89% in Speedometer
3. Specifically, it reduces CPU time in
`AXObject::SerializeInlineTextBox` by 34.49%.

Previously, serializing an inline text box cloned text shaping results
onto the heap to compute character pixel offsets. It also copied offset
arrays multiple times. In addition, it extracted the same text twice to
find word boundaries. Now, Blink computes character ranges directly from
the shaping view without heap cloning. Blink also moves offset arrays
directly into node data. Finally, Blink reuses the computed text and
direction when finding word boundaries. This change does not alter
accessibility behavior.

[protobuf] Add a git helper to roll_protobuf.py and use it for the cache

roll_protobuf.py has grown faster than the work it does, and the coming
roll milestones (plan, apply, finalize) each add a subcommand. This is
the first of five CLs that rewrite the existing `check` code in a
plainer style so those follow-ups stay small. Behavior is unchanged in
each of them, and roll_protobuf_test.py is not touched.

This one adds _RunGit(), which runs a git command line in the isolated
environment and raises RollProtobufError with git's stderr when the exit
code is unexpected. The upstream cache code moves over to it:
_ResolveCommitHash(), _IsValidGitRepository(), _FetchRevisionIntoCache()
and EnsureUpstreamCommitCached(). The bare clone is inlined into
EnsureUpstreamCommitCached(), its only caller, and the cache path and
commit hash constants are inlined into their only users. Docstrings
that restated the signature are gone; comments that explain past bugs
stay.

Incidental differences for git commands run through _RunGit(): stdin
comes from /dev/null instead of being inherited, and output is read as
bytes, so git's stderr in error messages is decoded as UTF-8 with
replacement characters instead of strictly in the locale encoding.
