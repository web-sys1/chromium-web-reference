Disallow direct launch scheme on renderer navigations

Ensure any renderer-initiated navigation targeting direct launch schemes
(google-chrome: and chromium:) is disallowed in Blink and does not
trigger an external protocol launch.

TODAY: The google-chrome: and chromium: direct launch schemes target a
specific Chrome instance. Previously, when a web page navigated to
google-chrome:https://example.com, ChromeContentBrowserClient
intercepted the external protocol and opened the inner URL with
is_renderer_initiated = false.

PROBLEM: Laundering a renderer-initiated navigation into a
browser-initiated navigation (is_renderer_initiated = false) creates a
privilege escalation vulnerability. Web pages can bypass renderer
sandboxing (e.g., iframe allow-scripts or allow-top-navigation), Content
Security Policy (CSP), and initiator origin checks by prefixing target
URLs with google-chrome:.

SOLUTION: Block direct launch scheme navigations from web contexts:

1. Renderer (Blink): When a web page navigates to a google-chrome: or
   chromium: URL, FrameLoader blocks the navigation, logs a DevTools
   console security error, and cancels the load. Includes a TODO
   to explore prefix stripping for web compatibility in the future.

2. Browser (ChromeContentBrowserClient): Since legitimate renderer
   navigations are blocked in Blink, receiving an un-stripped direct
   launch scheme from a renderer document indicates a compromised
   renderer. The browser process terminates the renderer via
   bad_message::ReceivedBadMessage(CCBC_GOOGLE_CHROME_SCHEME).
