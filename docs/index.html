[Notifications] Guard chrome/ and renderer against empty IDs

Earlier CLs fixed the root cause: crrev.com/c/8563327 makes
NotificationDatabase reject records with an empty notification_id and
guards PlatformNotificationContextImpl, and crrev.com/c/8562221 rejects
empty IDs sent to ClosePersistentNotification over Mojo. Other entry
points can still pass an empty or invalid notification ID down to CHECKs
in NotificationEventDispatcherImpl and NotificationDatabase.

Guard PersistentNotificationHandler::OnClose, OnClick and OnMaybeReport
against an empty notification ID or invalid origin. Each returns early,
runs the completion closure and records kDatabaseError in the close and
click result histograms. This replaces the CHECK(origin.is_valid()) in
OnClose. Also skip empty IDs in the Android NotificationSuspender,
reject Windows launch IDs whose notification ID is empty, and skip
closing a persistent notification without an ID in the Blink renderer.

Replace CHECK(IsPersistentNotification()) in
DoReadAllNotificationDataForServiceWorkerRegistration with dropping and
deleting the record, since a corrupted entry could otherwise crash the
browser once the CHECK becomes fatal in M159.

VT: Avoid duplicate capture render pass when there are no nested elements

Previously, AddSurfaceToRenderSurfaceList unconditionally marked every ViewTransition capture surface with set_has_view_transition_capture_contributions(true). This caused CalculateRenderPasses to always generate both a regular render pass and a separate CreateViewTransitionCaptureRenderPass for every captured element (including the root surface during cross-document transitions or leaf captured elements), even when there were no nested ViewTransition elements to exclude.

Instead, only set has_view_transition_capture_contributions(true) during the ancestor walk in ComputeInitialRenderSurfaceList when a captured surface actually has a descendant capture surface that is being captured in the current frame (and on the intermediate surfaces between them). When a surface has no nested capture contributions, its regular render pass and capture pass have identical content and clip bounds, so we can attach the ViewTransitionElementResourceId directly to the single regular render pass.

[Cronet] Catch Exception when listing JUnit4 tests

In https://crrev.com/c/8596233, the catch block in
BaseChromiumAndroidJUnitRunner#listTests() was narrowed from
`IOException | RuntimeException` to `RuntimeException` because the
rolled version of `androidx.test:runner` in Chromium no longer declares
`throws UnsupportedEncodingException` on
`TestExecutor#execute(Request)`.

However, Cronet's gn2bp build in Android compiles this class against
Android's prebuilt `androidx.test.runner`, which is still on an older
version that declares `throws UnsupportedEncodingException`. Catching
`Exception` satisfies javac in both Chromium (since JLS 11.2.3 exempts
`Exception` from unreachable checked exception errors) and Android.
