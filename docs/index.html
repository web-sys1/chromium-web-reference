[viz] Fix unverified SyncToken DCHECK in ClientResourceProvider

In ClientResourceProvider::PrepareSendToParent(), when no
SharedImageInterface is provided, a DCHECK ensures that none of the
imported resources have unverified SyncTokens. However, the current code
deems empty SyncTokens as unverified. This causes issues when the
UseAutomaticSyncTokenManagement feature is enabled (in the future),
which makes the SyncTokens empty. Also, the predicate was named
`check_is_verified` but it actually return true when SyncToken is
*unverified*. This may cause unintended confusions.

In this CL, we made the following changes:

1. Change `check_is_verified` to `check_is_empty_or_verified` and add a
check for the empty SyncTokens. Now the predicate performs exactly what
its name indicates.

2. Replace `std::none_of` with `std::all_of`. (i.e. changing the
semantics from "none of the SyncTokens are unverified" to "all of the
SyncTokens are verified"). This makes the code more straightforward by
avoiding double negatives.

This CL is a prerequisite before enabling
UseAutomaticSyncTokenManagement.
