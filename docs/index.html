Use Desktop-allowlisted string IDs in GlicToastBrowserTest

On official Windows Chrome builds, enable_resource_allowlist_generation
strips GRIT string resources whose IDs are not referenced in production
code linked into chrome.dll. GlicToastBrowserTest passed
IDS_GLIC_CHAT_HIDDEN_TITLE, IDS_GLIC_CHAT_HIDDEN_DESCRIPTION,
IDS_GLIC_TASK_PAUSED_TITLE, and IDS_GLIC_TASK_PAUSED_DESCRIPTION, which
are only referenced in Android-only production code, causing
ui::ResourceBundle::GetLocalizedString to CHECK-crash across five
GlicToastBrowserTest cases on chrome/ci/win64:
- ShowWithTitleAndDescription
- ShowWithTitleOnly
- DestroyBeforeExpiryIsSafe
- AutoDismissSetsIsShowingFalse
- ReassignWhileShowingPreemptsAndTransitions

https://ci.chromium.org/ui/test/chromium/%3A%2F%2Fchrome%2Ftest%5C%3Abrowser_tests%21gtest%3A%3AGlicToastBrowserTest%23ShowWithTitleAndDescription

Replace those sample string IDs with Glic string IDs referenced in
cross-platform production code linked into chrome.dll.

[CodeHealth] Use IntentUtils for extras in CustomTabsConnection

maybePrefetchResources() and maybeStartParallelRequest() read some
extras with the raw Intent#getParcelableArrayListExtra() and
Intent#getIntExtra(), while the neighboring extras already go through
IntentUtils. The intent comes from a third-party Custom Tabs client, so
switch them to IntentUtils.getParcelableArrayListExtra() and
IntentUtils.safeGetIntExtra(). Avoids crashing on malformed extras from
third-party callers.

The safe variants return null / the default value on failure, which is
already handled by the existing checks. The referrer policy is now read
after the early returns that don't need it.
