Mac: Depend on chrome_framework via data_deps in chrome/app:test_support

On Mac, browser_tests C++ object compilations are blocked until the
linking of //chrome:chrome_framework finishes, which unnecessarily slows
the build.

The reason is because chrome_framework is a create_bundle target and
also a GN dep of //chrome/app:test_support (which is an indirect dep of
the browser_tests target). However, chrome_framework is only needed at
runtime by the test_support target.

Therefore, we move chrome_framework to be a data_dep (instead of a dep)
of test_support.

Also, remove dead code from chrome/app/chrome_main_mac.h.
