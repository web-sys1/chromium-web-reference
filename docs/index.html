[WebUI LLBC] Migrate location icon to toolbar-chip-button

The location icon used its own <button>, with very similar css as
toolbar-chip-button already provides.

toolbar-chip-button changes (all opt-in; other chips unchanged):
- Add a buttonRole property to set the inner button's ARIA role.
  The security chip can be exposed as an image.
- Add disable-hover(/pressed)-highlight to turn off :hover/:active
  ink. The location icon turns both off when it isn't clickable.
- Add --toolbar-chip-label-side-spacing so chips that set their own
  padding can drop the automatic H/4 label padding.

Location icon changes:
- Keep id="button" on the chip, so existing pointer capture code and
  JS/C++ test queries still find the clickable element.
- The location icon still animates its own label, so it always sets
  has-label to stop the chip from hiding it.
- Show the bubble-anchor highlight by toggling is-menu-open on the
  inner chip, matching other toolbar chips.
- Use HelpBubbleAnchorMixin so the IPH pulse class is passed on to
  the chip. The old class on location-icon can't reach the button
  inside the chip's shadow root.

Known differences, all inherited from toolbar-chip-button and matching
the other chips:
- The hover/pressed ink now draws under the icon and label instead
  of over them. Native LocationIconView draws it on top
  (LayerRegion::kAbove), as do the native views of every
  toolbar-chip-button user. This will be fixed in
  toolbar-chip-button in a follow-up.
- With prefers-reduced-motion, the IPH pulse now plays, matching
  other chips, and matching native views.
- Bugs tracked in bug crbug.com/572066807

Ash: Move web app run-on-OS-login notification to MessageCenter

When an administrator has set web apps to start automatically at login,
ChromeOS shows a notification naming the apps, and clicking it opens
chrome://management. This CL migrates DisplayRunOnOsLoginNotification()
from NotificationDisplayService to MessageCenter.

Keep the notification scoped to the user whose profile shows it, as
NotificationDisplayService did: derive its ID with
ash::CreateUserScopedNotificationId and set NotifierId::profile_id, so
that it is hidden while another signed-in user is active.

The file only builds on ChromeOS, so also drop its non-ChromeOS #else
branch, which this CL would otherwise leave next to unguarded Ash calls.
The //chrome/browser/notifications deps of ui/web_applications stay for
web_app_relaunch_notification.cc, which a follow-up CL migrates.

Update the unit and browser tests to use MessageCenter instead of
NotificationDisplayServiceTester.

AppendRevisedTextSelectionSection() were directly calling
CanPartiallyTranslateTargetLanguage() and AppendPartialTranslateItem()
without verifying:
1. The platform is not ChromeOS (!BUILDFLAG(IS_CHROMEOS)). On ChromeOS,
   selection translation is handled by Ash Quick Answers / Read Write
   Cards, and translate should not be appended in selection or editable
   context menus.
2. The default search provider is Google
   (search::DefaultSearchProviderIsGoogle(GetProfile())).
3. The page / URL can be translated
   (CanTranslate(/*menu_logging=*/false)).

This CL consolidates translation checks in simplified context menus into
a helper AppendTranslateOrPartialTranslateItem() to ensure all requisite
guards are respected.

Unit tests are added covering these guards and ChromeOS behavior.

[Mac] Preserve pending work wakeup when quitting a nested RunLoop

On macOS, when a nested RunLoop running
MessagePumpNSApplication::DoRun() is started from inside a native
event dispatch (such as an internal AppKit drag loop inside
-[NSApplication sendEvent:]) and is later quit by a task that also
schedules follow-up work for the outer RunLoop:

1. Quit() sets keep_running_ = false and posts a dummy
   NSEventTypeApplicationDefined event to wake up the pump.
2. Follow-up work scheduled before DoWork() returns signals
   work_source_.
3. While draining the dummy event via -[NSApp nextEventMatchingMask:],
   the CFRunLoop runs again to check for events, which fires
   work_source_ and consumes its pending signal.
4. However, RunWork() returns early without doing work or re-signaling
   work_source_ because keep_running() is false.

Once the nested DoRun() finishes and restores keep_running_ = true,
the outer RunLoop resumes inside -[NSApplication sendEvent:] without
knowing that work_source_ was signaled, causing the outer RunLoop to
hang until an unrelated event wakes it up.

Fix this by recording signaled_after_quit_ = true when RunWork() is
invoked while !keep_running(), and re-signaling work_source_ in Run()
once DoRun() exits.

callers need no #if wrapping.

kEnterpriseExtensionActorAttribution feature (disabled by default), a
single flag intended to cover all enterprise extension actor
attribution. It is checked both in the router and in
GetExtensionInitiatorInfo().

wired up in a follow-up CL stacked on this one.

Respect --disallow-v8-feature-flag-overrides for DCHECK_IS_CONFIGURABLE

In builds with dcheck_is_configurable = true (where dcheck_always_on is
also enabled and V8 is built with DEBUG defined), RenderProcessImpl
overrides V8's default --turbo_verify, --turbo_verify_allocation, and
--debug_code flags when base::kDCheckIsFatalFeature is disabled.

runs with default V8 flags and disallows V8 feature flag overrides.

was not gated on !disallow_v8_feature_flag_overrides, TopChrome WebUI

[network] Allow kSameOrigin credentials with disable_web_security

crrev.com/c/8278433 moved the evaluation of CredentialsMode::kSameOrigin
from CorsURLLoader to url_loader_util::SetRequestCredentials() via
IsSameOriginOrAccessAllowed(). However, when URLLoaderFactoryParams has
disable_web_security enabled (e.g. via --disable-web-security or
Android WebView's allow_universal_access_from_file_urls for file://
origins), CorsURLLoaderFactory bypasses CorsURLLoader and
origin_access_list is not populated for arbitrary cross-origin targets.
As a result, cross-origin requests with default kSameOrigin credentials
mode had their credentials disallowed in SetRequestCredentials().

Pass URLLoaderFactoryParams::disable_web_security to
SetRequestCredentials() during initial request configuration and on
redirects, and allow kSameOrigin credentials and client certificates
when disable_web_security is true, guarded by a new kill-switch feature
kAllowSameOriginCredentialsWithDisableWebSecurity.

[Journeys] add a single-query journey history entry lookup

Resolving a journey's visits currently runs two queries per history
entry (GetLastRowForVisitByVisitTime and GetURLRow), which adds up when
all journeys are resolved at once. Add JourneysDatabase methods that
look up the history entries of one or all journeys with a single query
joining them with visits and urls, reporting per entry whether the
visit or URL is missing.

The lookup follows the existing resolution semantics: the visit with
the largest ID for a timestamp is used (the end of a redirect chain),
and a URL row with an invalid URL counts as missing. Resolution
switches over in a follow-up CL.

[chromium-bidi] Implement autofill.trigger

Implement the `autofill.trigger` WebDriver BiDi command defined by the
Autofill Event specification [1], by mapping it to CDP
`Autofill.trigger`, which waits for provided inputs and then This is a
port of [2], updated to the specification as published.

Bidi:
- Generate the `autofill` module types from the WICG/autofill-event spec
  with `tools/update_bidi_types.py`. Teach the generator to import core
  namespaces referenced by extension specs, e.g.
  `browsingContext.BrowsingContext` and `script.SharedReference`.
- Add `AutofillProcessor`, which checks that the element is a form
  control with a form owner and that exactly one of `card` and `address`
  is provided, maps `autofill.FieldName` values (HTML autofill field
  names) to Chromium autofill field types, and maps CDP errors to BiDi
  errors.
- Add unit tests and E2E tests, including same-origin and cross-origin
  iframes.

CDP:
- Make `Autofill.trigger` respond only once the values have been applied
  to the form fields, so that clients can read them as soon as the
  command returns, without polling. After sending the values to the
  renderers, the handler triggers form extraction in all frames and
  responds when it finishes. Form extraction goes over the same
  `mojom::AutofillAgent` pipes as the fill, so by then the renderers
  have applied the values.
 - Document this in `Autofill.pdl`, and add
  `DevToolsAutofillTest.TriggerRespondsAfterFillIsApplied`.
