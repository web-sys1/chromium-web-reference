[iOS] Include open Shadow DOM content in page context extraction

Page context extraction on iOS walked the DOM via a TreeWalker and read
Element.innerText, neither of which crosses shadow boundaries. As a
result, content rendered inside open shadow roots (increasingly common
with web components) was missing from both the inner-text tree and the
annotated page content (APC).

This CL pierces open shadow roots in both extraction paths:

- Annotated page content: the subtree walk is factored into
  walkTreeAndPopulate(), which recurses into a host's open shadow root
  and grafts the shadow tree as children of the host node. This mirrors
  desktop Blink's APC extraction, which walks the composed (flat) tree.
  The shadow descent is independent of whether the host itself produces
  an APC node, so shadow content is preserved even for node-less hosts.

- Inner-text tree: getInnerTextIncludingShadowDom() collects
  Element.innerText and additionally descends into open shadow roots,
  handling nested shadow roots recursively and including direct
  text-node children of a shadow root.

Closed shadow roots are inaccessible from script and are skipped. Shadow
root and querySelectorAll access goes through Element.prototype getters
to avoid page clobbering.

Adds PopulatePageContextWithShadowDom to verify that both inner text and
APC include open (including nested) shadow content while excluding
closed shadow roots.
