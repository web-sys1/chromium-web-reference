[omnibox] use is_full_webui_omnibox() instead of the feature flag

The Full WebUI Omnibox feature flag was being used in ~30 places as a
proxy for "this omnibox is a Full WebUI omnibox", when it is not one.
LocationBarView::Init() only constructs OmniboxPopupViewFullWebUI when
the flag is enabled *and* the window is not a popup window, web app, or
DevTools window. Otherwise it falls back to the classic Views popup, or
to OmniboxPopupViewBrowserView when the Omnibox_UseBrowserView param is
set. Every flag-as-proxy call site therefore misbehaves in those
windows.

Introduce OmniboxPopupPresenterDelegate::is_full_webui_omnibox() so
callers can ask the instance what it actually is, and convert the
popup-layer call sites to it. LocationBarView caches the answer at
construction via a shared CanHostWebUIOmnibox() helper, now correctly
including the !is_popup_mode term that the bare flag check omitted.

Because OmniboxPopupPresenterDelegate gains a pure virtual, all of its
implementers are necessarily updated in this CL.

Follow-up CLs separate "is Full WebUI" from "Full WebUI is ready", and
move the feature flag into omnibox::internal.
