[WebAudio] Refactor and optimize AudioParam sizing in AudioWorklet

AudioWorkletProcessor::Process previously scanned all 128 float elements
in ParamValueMapMatchesToParamsObject and CloneParamValueMapToObject on
every render quantum to check whether an AudioParam had constant values.
Meanwhile, AudioWorkletHandler always passed full 128-element buffers
regardless of automation rate or sample accuracy.

This CL moves the sizing logic into AudioWorkletHandler with zero
audio-thread heap allocations:
- Pre-allocate backing AudioFloatArray buffers (`param_buffers_`) to
  RenderQuantumFrames() on the main thread and expose active
  `base::span<const float>` views in `param_value_map_`.
- Share SIMD-accelerated `audio_utilities::HasConstantValues()` between
  BiquadFilterHandler and AudioWorkletHandler to slice constant or
  k-rate parameter spans to length 1 and varying sample-accurate a-rate
  spans to `frames_to_process`.
- Remove the redundant O(N) per-quantum loops in AudioWorkletProcessor
  and use `param_values.size()` directly.
- Add unit tests covering `AudioWorkletProcessor::Process` size
  transitions and `AudioWorkletHandler::Process` parameter sizing.

[TabModel] Consolidate onTabGroup* callbacks onto TabGroupObserver

TabModelObserver previously duplicated tab group lifecycle callbacks
(onTabGroupCreated, onTabGroupRemoving, onTabGroupMoved, and
onTabGroupVisualsChanged) alongside TabGroupObserver solely so
TabModelObserverJniBridge could forward group events to native
observers. This forced TabCollectionTabModelImpl to iterate all
registered TabModelObservers on every tab group creation, move, visual
update, and removal even though TabModelObserverJniBridge was the only
consumer.

Have TabModelObserverJniBridge implement TabGroupObserver directly, move
onTabGroupVisualsChanged to TabGroupObserver, and remove the duplicate
callbacks and observer loops from TabModelObserver and
TabCollectionTabModelImpl. Routing willRemoveTabGroup through
TabModelObserverJniBridge also ensures native observers receive
OnTabGroupRemoving when a tab group is dissolved via ungrouping,
merging, or group creation undo.

[Extensions] Fix ScriptInjectionTracker desync for RequestContentScript

Previously, RequestContentScript::InstructRenderProcessToInject() used
PermissionsData::CanAccessPage() to check if an extension could inject a
declarative content script into a frame. Because CanAccessPage() returns
true even when host permissions are withheld, the browser invoked
ScriptInjectionTracker::WillExecuteCode() prematurely before sending
ExecuteDeclarativeScript() to the renderer. In the renderer,
ScriptInjection::TryToInject() detected that permissions were withheld
and deferred execution. This caused the browser and renderer states to
desynchronize: the browser erroneously considered the renderer process
as having executed the extension's content script even though no script
ran.

With this change, the browser does not update ScriptInjectionTracker
when page access is withheld during declarative content script
evaluation. Instead, the renderer defers the script and requests
permission via ExtensionActionRunner. Once the user explicitly grants
permission on the tab, the deferred script executes in the renderer and
ScriptInjectionTracker is updated so browser and renderer states remain
synchronized.

We update RequestContentScript::InstructRenderProcessToInject() to query
PermissionsData::GetPageAccess() directly and only call
ScriptInjectionTracker::WillExecuteCode() when access is kAllowed. We
also add mojom::InjectionType::kDeclarativeScript, which
UserScriptInjector reports for RequestContentScript scripts, and have
ExtensionActionRunner gate it on PermissionsData::GetPageAccess() so
withheld requests are queued. ExtensionActionRunner already notifies

[WebUI Toolbar] Align home button plain-text drop behavior on macOS

Aligns drag-and-drop on the WebUI toolbar home button with the native
Views HomeButton on macOS.

The native HomeButton only accepts drops that carry a URL. On macOS,
ui::clipboard_util::URLsAndTitlesFromPasteboard() already synthesizes a
URL from URL-like plain text, so such drags reach the WebUI toolbar as
`text/uri-list` and are routed to OnHomeButtonDropUrl(). A drop that is
still `text/plain` only therefore carries no URL, and the native button
ignores it regardless of where the drag started.

WebUIHomeControl::ShouldHandleDropText() now returns false on macOS for
every `text/plain`-only drop, and consumes the pending drag origin state
so it does not leak into later navigations.

[GEiC] Add purpose-keyed OpenAuthTab/CloseAuthTab for connector OAuth

The GEiC side panel is a privileged WebContents, so `window.open()` is
denied and 3P connector OAuth has to run in a browser tab. The GE client
currently opens that tab through glic's generic `createTab`, but has no
way to close it afterwards: script-initiated `window.close()` is blocked
for such tabs, so users are left on a "please close this tab" page.

Add a single `OpenAuthTab` / `CloseAuthTab` pair to
`GeminiEnterpriseHandler`, keyed by a fixed `AuthTabPurpose` enum
(`kSignIn`, `kConnectorOauth`):

* Each purpose has its own browser-side URL allowlist, its own tracked
  tab, and its own UMA (`Geic.AuthTab.{Open,Close}Result.{Purpose}`).
* `kConnectorOauth` only accepts the GE OAuth redirector
  (`/oauth-redirect` on the default redirector origin
  `vertexaisearch.cloud.google.com` or the guest origin); the 3P
  provider in `continue_uri` is intentionally not validated. A reused
  OAuth tab is navigated, since each flow has a fresh `state`.
* A tracked tab is only reused or closed while it is still on an origin
  expected for its purpose; if the user navigates it elsewhere, it is
  left open (`CloseAuthTabResult::kNavigatedAway`). `CloseAuthTab` can
  only close the tab Chrome opened for that purpose, and restores focus
  to the previously active tab only if the closed tab was still active.
  There is no generic close-arbitrary-tab capability.
* Unknown purposes (e.g. from a newer client via the [Extensible]
  default) are rejected.

The open/track/close/restore-focus logic moves from
`GlicGeminiEnterpriseManager` into a new `GeicManagedTab` helper.
`OpenSignInTab` / `CloseSignInTab` are kept as deprecated aliases for
`kSignIn` so existing clients keep working. The TS methods are optional
on `GeicBrowserHost` so the client can feature-detect them.
