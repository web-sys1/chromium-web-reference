[rlz] Disable ConcurrentStoreAccessWithProcessExitsWhileLockHeld on Mac

RlzLibTest.ConcurrentStoreAccessWithProcessExitsWhileLockHeld tests
cross-process lock recovery by spawning 10 child processes via fork()
without exec(), having some exit while holding the lock, and checking
that the remaining processes succeed.

On modern macOS in multi-threaded test runners (gtest/XCTest), invoking
Objective-C/Foundation APIs in a child process after fork() violates
Apple's fork-safety checks in libdispatch/libobjc, causing all child
processes to crash with SIGABRT or deadlock.

Disable this test on macOS with an explanatory comment.
