[UndoTabClosures] Route TabGridDialogMediator undo snapshots through UndoClosureRestorer

Under kUndoableTabClosureRework, closed tabs will be finalized and saved
at close time and the undo snackbar will carry an UndoClosureSnapshot.

Teach TabGridDialogMediator's snackbar controller to handle that
payload: onAction restores the closed tabs via UndoClosureRestorer
(reselecting the previously selected tab), and onDismissNoAction does
nothing since the closure is already committed. The existing
pending-closure payloads keep their current behaviour.

Snapshots are not yet produced for the dialog; a follow-up CL starts
delivering them when the rework flag is enabled.

[User Ed] Add UserEducationEnterprisePolicy flag to gate PromotionsEnabled on Android

Adds a dedicated UserEducationEnterprisePolicy feature flag and updates
TrackerFactory so the enterprise policy supplier only checks the
PromotionsEnabled local-state pref when both UserEducationFramework and
UserEducationEnterprisePolicy are enabled. This lets us roll out
enterprise policy enforcement for Android IPH independently of the rest
of the User Education framework and gives it its own kill switch. The
new flag is disabled by default; when either flag is off the supplier
returns false so enterprise policy never blocks promotions, matching
today's behavior.

MediaRecorder: Coarsen time in pause passed to the muxer

MuxerTimestampAdapter measured time in pause with an ElapsedTimer and
subtracted it from the frame timestamps. Since pause() and resume() are
called synchronously from JS, the raw pause duration reappeared in the
muxed output at sub-100 us resolution despite the frame timestamps being
coarsened.

Fix this by having MuxerTimestampAdapter::Pause()/Resume() take the
current time, which MediaRecorderHandler coarsens like the frame
timestamps.

Android: Add FieldCanBeFinalFast Error Prone check (disabled)

Adds a temporary copy of Error Prone's FieldCanBeFinal check to
//third_party/android_build_tools/error_prone/java that avoids calling
SuggestedFixes.compilesWithFix(). The upstream check calls
SuggestedFixes.compilesWithFix() for every candidate field, which
re-attributes the compilation unit and makes it one of the slowest
checks that Chromium enables.

The copy is named FieldCanBeFinalFast, and has "FieldCanBeFinal" as an
altName so that existing @SuppressWarnings("FieldCanBeFinal") also
suppress it. It keeps the original Error Prone copyright and Apache-2.0
license header, and is described in README.chromium.

It is compiled into //tools/android/errorprone_plugin via a new
java_library, and 3pp.py compiles it into the error_prone native-image
along with the plugin's other checks. The native-image's tracing run
now also traces FieldCanBeFinalFast on javac's sources, and
_SAMPLE_JAVA gains a field so that FieldCanBeFinal is traced on it
(FieldCanBeFinal crashes on javac's sources).

The check does nothing unless -XepOpt:FieldCanBeFinalFast:Enabled=true
is passed, so this change has no effect on builds. errorprone.py cannot
use -Xep:FieldCanBeFinalFast:OFF to keep it off, because the Error Prone
native-image that errorprone.py uses on linux-x64 does not yet contain
the check, and so fails with "FieldCanBeFinalFast is not a valid checker
name". The flag also keeps it from running when -Xep:FieldCanBeFinal
enables it via its altName. A follow-up enables it in place of
FieldCanBeFinal, once the error_prone 3pp package has been rebuilt to
include it.

3pp.py copies the new java directory to a different path within the
3pp checkout, since the 3pp recipe copies the package definition to
.3pp/chromium/third_party/android_build_tools/error_prone, and fails if
that directory already exists. It also passes the flag that enables the
check.

The copy should be deleted once Error Prone's upstream check picks up
this fix.

WebMCP: Hide debugging tools from AI consumers of page content

WebMCP tools registered with the `debugging: true` annotation are
intended for developer tooling only, and must not be exposed to AI
consumers such as the Chrome actor layer.

This CL adds an `include_debugging_script_tools` option (default false)
to the `AIPageContentOptions` mojom. When generating the AIPageContent
in the renderer, script tools annotated with `debugging: true` are now
dropped unless the option is set.

CDP `Page.getAnnotatedPageContent` gains an optional
`includeDebuggingTools` parameter (default true, preserving current
behavior), handled by the Chrome and headless DevTools PageHandlers.
CDP clients have different needs (DevTools vs. automation or agents
built on headless), so each client decides whether it wants debugging
tools.

[Bookmarks] Avoid redundant view rebuilds on edit/picker exit

BookmarkModel#moveBookmarks fires one bookmarkModelChanged() per node
and a title+URL save one per write. The folder picker rebuilt its folder
list N times inside the move click before finish(), and the edit dialog
re-inflated its folder row each time, on the main thread right before
RenderProxy::setStopped.

- Post a coalesced refresh from bookmarkModelChanged() via
  PendingRunnable + CallbackController (same pattern as
  BookmarkManagerMediator), cancelled in destroy()/onDestroy().
- Skip the refresh in BookmarkEditActivity when isFinishing().
- Skip the title/url JNI writes in saveBookmark() when unchanged; the
  title write previously ran on every onStop().
- Hold and destroy BookmarkImageFetcher in both activities.

This removes verifiable main-thread teardown work but isn't proven to
be the whole ANR, so the bug stays open for a canary before/after.

[Zoom] Re-enable `IFrameZoomBrowserTest.SiblingFramesZoom` on macOS

`IFrameZoomBrowserTest.SiblingFramesZoom` was disabled on macOS in
https://crrev.com/c/2273622 due to flakiness when
`FrameResizeObserver::SetupOnResizeCallback` called `ExecuteScript`.
Because `ExecuteScript` used `window.domAutomationController.send`
internally, an `onresize` message sent by the first child frame could
collide with `ExecuteScript` while setting up the second child frame's
observer.

Subsequently, https://crrev.com/c/2826401 migrated
`FrameResizeObserver::SetupOnResizeCallback` from `ExecuteScript` to
`ExecJs`, which uses a dedicated Mojo callback instead of
`domAutomationController`, and https://crrev.com/c/3634680 scoped
`DOMMessageQueue` to `web_contents()`. Re-enable `SiblingFramesZoom` on
macOS.

Part of http://go/arthurmilchior-fix-all-test-skill-chrome for AI week.
