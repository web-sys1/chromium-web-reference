[WebUI Toolbar] Force reduced motion in UI tests

Toolbar animations change element bounds mid-transition, which can make
overflow interactive UI tests flaky when clicking the overflow button.
Previously, only one overflow test disabled animations via an async JS
override on AnimationTracker, leaving animations active in the other
overflow tests and leaving @media (prefers-reduced-motion: reduce) CSS
rules inactive. Separately, avatar-button had no test verifying that
reduced motion suppresses its label transitions.

Pass --force-prefers-reduced-motion across
WebUIToolbarFullyEnabledInteractiveUiTest instead of the per-test JS
helper, and add AvatarButtonTest.RespectsReducedMotion running under
both reduced-motion and non-reduced-motion Mocha browser test fixtures.

Fix VSync propagation race in cross-origin-iframe-with-nesting.html

cross-origin-iframe-with-nesting.html nests two cross-origin iframes
across three processes (Frame A -> Frame B -> Frame C). When Frame A
scrolls in step3, each cross-origin boundary calls
LocalFrame::SetViewportIntersectionFromParent(), which schedules an
animation rather than synchronously forwarding intersections, requiring
three sequential BeginMainFrame cycles (Frame A, Frame B, Frame C)
before Frame C computes its IntersectionObserverEntry.

Previously, nested-cross-origin-subframe.html only waited for one ACK
round-trip (two top-frame rAF cycles), allowing step3 to call
observer.takeRecords() before Process C ran its BeginMainFrame. Wait for
at least two ACK round-trips and, for steps expecting entries, continue
polling ACK frames until Process C has recorded the entry.
