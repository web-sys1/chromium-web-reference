Fix Built-In AI WebDX feature names and add WPT WEB_FEATURES.yml files

1. The WebDXFeature enum name and histogram label map to W3C
web-features IDs by splitting CamelCase on capital letters with hyphens.
Because buckets 420 and 425 were named kLanguageModel /
label="LanguageModel" and kLanguageDetector / label="LanguageDetector",
the pipeline exported them as "language-model" and "language-detector"
instead of the actual web-features IDs "languagemodel" and
"languagedetector". Rename them to kLanguagemodel and kLanguagedetector
and update enums.xml accordingly.

Note: While an alternative would be keeping kLanguageModel /
kLanguageDetector in Chromium and renaming the upstream YAML files in
web-platform-dx/web-features to use dashes (language-model.yml and
language-detector.yml with redirects), doing so requires too many
external steps (upstream W3C repo PR review, a new web-features npm
release, and downstream dependency bumps in webstatus.dev and wpt.fyi).
Aligning Chromium's enum names directly with the published web-features
identifiers fixes the dashboards immediately in a single step.

2. Add missing WEB_FEATURES.yml files for all Built-In AI APIs present
in web-platform-dx/web-features:
- third_party/blink/web_tests/external/wpt/ai/language-model/WEB_FEATURES.yml ([languagemodel])
- third_party/blink/web_tests/external/wpt/ai/language_detection/WEB_FEATURES.yml ([languagedetector])
- third_party/blink/web_tests/external/wpt/ai/translator/WEB_FEATURES.yml ([translator])
